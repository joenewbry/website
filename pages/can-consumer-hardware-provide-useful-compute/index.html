Can consumer hardware provide useful compute?

Yes—for the right model. Macs can run useful local reasoning; phones work best with smaller models and bounded tasks.

Why the charts are not a universal device ranking

The Mac chart uses Llama 2 7B Q4_0, an older non-reasoning benchmark. M2–M4 use build 8e672ef; M5 submissions use newer software. The iPhone chart uses TinyLlama 1.1B Q4_0; its Air result uses a newer runtime. Neither chart predicts a specific reasoning model’s speed.

Android is represented by five Snapdragon flagship generations, not every Android vendor. Its older rows use different workloads; only the two Qwen3-1.7B GenieX rows form a closely matched pair. Pixel/Tensor, Exynos and MediaTek phones require separate tests.

Coverage uses the five latest announced generations as of the research date: M2–M6, iPhone 14–18, and Snapdragon 8 Gen 2 through 8 Elite Gen 6. M6 MacBook Pro was announced today and is due November 6; announcements are not measured performance.

The 32 GB M2 Pro is a published reference machine, not the assumed newer Mac. Its Qwen3 rate falls from 96.3 to 54.9 tokens/s when context grows from 4K to 16K. Liquid’s examples use 1K input and 100 output tokens. These are short runs, not sustained capacity measurements.

Fast tokens can still mean a long wait

A reasoning model may produce thousands of thinking tokens before its final answer. Explore the generation time for a 256-token answer.

generation time

Scenario calculation: (thinking tokens + 256) ÷ tokens/s. Add model loading, prompt processing, queue and network time. It holds speed constant; it does not predict how many tokens a model needs or whether its answer is correct.

Reasoning models that fit

My starting choices: Qwen3-1.7B on the iPhone, Qwen3.5-4B or DeepSeek-R1-0528-Qwen3-8B on the 16 GB Mac, and gpt-oss-20b on the 32 GB Mac. These are practical trial candidates, not a quality leaderboard.

B means billion model parameters. Approximate download sizes assume a compact quantized build—usually 4-bit, which stores weights at reduced precision. Sizes vary by package and are not total working memory. Fit judgments are planning recommendations at short context, not measured compatibility certifications.

Model licenses and reasoning modes

Qwen models listed here use Apache 2.0; the DeepSeek distills use MIT; gpt-oss uses Apache 2.0. Liquid uses its own license, so check its terms before building a paid service. The model-name links lead to the original cards.

Qwen3-1.7B supports thinking and non-thinking modes. Qwen3.5-2B defaults to non-thinking; Qwen3.5-4B and 9B default to thinking. The dedicated Thinking and DeepSeek R1 variants are reasoning models. For gpt-oss, use the runtime’s supported reasoning-effort and chat-format handling.

Run the experiment with existing software

Mac: a small private worker

Use Ollama for straightforward model management, or MLX LM for an Apple-native inference and benchmark toolkit. Start with one model and one request at a time.

ollama run qwen3.5:4b
# On the 32 GB Mac:
ollama run gpt-oss:20b

These commands download model files. Nothing has been installed or benchmarked on your Macs as part of this page.

Phone: a bounded local task

PocketPal is an open-source iOS/Android starting point with model downloads and a benchmark screen. Confirm support for the chosen model; a compatible file format alone is not enough.

Begin with Qwen3-1.7B in a 4-bit GGUF package. For Android, Qualcomm’s optimized runtime is a separate integration path; its results should not be expected automatically in PocketPal.

For each device, record the model hash, quantization, app/runtime version, prompt length, generated tokens, time to first token, peak memory and a 20-minute sustained run. Test answer correctness on real tasks. This is the harness needed before advertising throughput or pricing.

Useful locally does not yet mean profitable compute

Memory capacity decides what fits. Memory bandwidth often limits one-at-a-time token generation. Sustained heat, competing apps and the amount of time a device is available affect how much work it can sell. Tokens per second alone cannot establish cost per watt; measure energy at the wall and completed, acceptable answers.

Unlimited phone data does not improve inference speed. It only helps transfer requests and model files; carrier conditions, background execution and heat still matter. A phone is a better first experiment for private on-device work than an always-available server.

For pooling your Macs, send whole jobs to a trusted idle worker and cache model files there. Tailscale protects the connection, but the receiving computer still sees the prompt. A work laptop should only participate within its owner’s device policy.
